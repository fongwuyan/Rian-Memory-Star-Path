## 0. 摘要

雨咯记忆星是一套**面向高频项目开发的跨会话长期记忆系统**，以「星图」组织记忆：

- **公共星图**：跨项目稳定信息（身份、语言、硬性偏好、协作约定），所有会话可见；
- **项目星图**：每个工作区一张，互相隔离，自动绑定；
- **星**：一条最小记忆单元；
- **星座**：项目图内的主题簇；
- **星云**：待确认区；
- **暗星区**：归档区。

核心闭环：**摘星（写）→ 归图（组织）→ 召回（读）→ 衰减（忘）**。

三条设计红线：

1. 记忆是插件自有数据，**不写进会话日志**，不新增事件类型；
2. 每轮召回是**纯本地计算**，不调 LLM，不阻塞对话；
3. 模型只能看到「公共星图 + 当前绑定项目图」，看不到其他项目。

---

## 1. 范围与定位

### 1.1 目标场景

- 同一个项目一天开很多会话、多个 agent 并行；
- 决策、约定、踩坑经验需要跨会话复用；
- 新会话不应该从零开始问「这个项目用什么包管理器」；
- 记忆必须便宜、快、可审计、可修正。

### 1.2 不做的事

- 不做 Bot 对话、多租户、按用户隔离；
- 不做云同步、多设备；
- 不做后台 LLM 自动提炼（由模型在对话中自行抽取）；
- 不设记忆数量硬上限（用权重管理注意力）；
- 不替换会话列表，不接管 shell。

### 1.3 成功标准

- 新会话首轮就能拿到项目简报；
- 相关记忆召回 p95 < 10ms，零额外模型调用；
- 一条错误记忆可以在 10 秒内被找到、修正或归档；
- 公共区写入永远不会绕过用户确认。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 星图（Map） | 一个记忆空间，分 `public` 与 `project` 两种 |
| 星（Star） | 一条最小记忆单元，一个主谓宾 |
| 星座（Constellation） | 星图内的主题簇，用于导航与批量操作 |
| 星云（Nebula） | 待确认区，`status = pending` 的星 |
| 暗星区 | 归档区，`status = archived` |
| 星尘 | 星的历史版本，保留最近 5 版 |
| 星等 | 由权重映射的视觉亮度分档 |
| 锚点（Anchor） | 记忆所属的工作区 / 分支 |
| refs | 记忆引用的文件路径、命令、版本号 |

## 3. 作用域与绑定

### 3.1 星图类型

| 类型 | 数量 | 可见性 | 模型写入 |
|---|---|---|---|
| `public` | 1 张，内置不可删 | 所有会话 | 一律进星云，待确认 |
| `project` | 每工作区一张 | 仅绑定它的会话 | ≥0.85 直接生效，否则进星云 |

公共星图只收跨项目稳定信息；项目相关的一切进项目图。

### 3.2 绑定规则

解析顺序（先命中先得）：

1. 会话级手动覆盖（composer chip）；
2. 工作区映射：`workspaceId → mapId`；
3. 默认：未绑定时只召回公共星图；
4. 首次进入某工作区：自动创建项目图并绑定，弹出 toast「已为 <名称> 创建星图」，提供撤销。

- 绑定按 session 缓存，chip 上标注来源：`自动` / `手动`；
- 绑定位只指向项目图；公共星图是额外的固定作用域，不参与「二选一」；
- 同一工作区的多个会话共享同一张项目图；
- 分叉会话继承父会话绑定；恢复会话按 session id 保留绑定；
- 公共星图永远参与召回。

### 3.3 权限矩阵

| 操作 | 模型 | 用户 |
|---|---|---|
| 读公共图 | ✅ | ✅ |
| 读当前项目图 | ✅ | ✅ |
| 读其他项目图 | ❌ | ✅ |
| 写当前项目图 | ✅ | ✅ |
| 写公共图 | ⚠️ 进星云 | ✅ 直接 |
| 删除星 | ❌（只能归档） | ✅ |
| 导出 / 导入 | ❌ | ✅ |

### 3.4 自动建图

- 名称取工作区文件夹名，重名追加序号；
- 颜色从调色板按序分配；
- 首次建图不写入任何记忆；
- 撤销窗口 10 秒，撤销后回到未绑定状态。

## 4. 数据模型

### 4.1 Star

```jsonc
{
  "id": "st_01J...",
  "mapId": "map_...",
  "title": "项目使用 pnpm",          // <= 20 字，画布标签
  "fact": "所有安装与脚本统一走 pnpm，禁止 npm/yarn。", // <= 120 字
  "reason": "lockfile 一致性与 CI 缓存。",             // <= 120 字，可选
  "condition": "仅限本仓库；临时脚本可用 npx。",        // <= 100 字，可选
  "type": "decision",                // fact|preference|decision|event|entity|procedure
  "tags": ["工具链"],
  "refs": ["pnpm-lock.yaml", "pnpm install"], // <= 5 条，每条 <= 120 字
  "importance": 0.7,
  "confidence": 0.95,
  "status": "active",                // pending|active|archived|rejected
  "disputed": false,
  "source": {
    "kind": "session",               // session|manual
    "sessionId": "s_...",
    "fromSeq": 12,
    "toSeq": 14
  },
  "anchor": { "workspaceId": "ws_...", "branch": "main" }, // branch 可选
  "createdAt": "2026-11-07T12:00:00Z",
  "updatedAt": "2026-11-07T12:00:00Z",
  "lastRecalledAt": null,
  "recallCount": 0,
  "validUntil": null,
  "pinned": false,
  "position": { "x": 0.42, "y": 0.61 }, // 手动布局时才有
  "version": 1,
  "mergedFrom": []
}
```

约束：

- `title`、`fact`、`reason`、`condition`、`refs` 超长直接拒绝，让模型重写；
- `type` 决定默认重要度与衰减参数；
- `anchor` 由宿主根据绑定关系自动补，模型不用传；
- `position` 只在用户拖动后写入。

**记录分层**：模型填写 `title / fact / reason / condition / type / tags / refs / confidence` → 宿主补全 `id / mapId / source / anchor / createdAt / status` → 系统维护 `weight / recall / disputed / version / history`。

**不可变字段**：`id`、`mapId`、`source`、`createdBy`、`createdAt`；其余可编辑；移动 / 提升会改写 `mapId` 并记历史。

**按类型模板**：

| 类型 | 标题写法 | 事实 / 理由 / 条件 | refs |
|---|---|---|---|
| decision | 主语 + 决定 | 决定 + 理由 + 影响 | 配置、命令 |
| fact | 主语 + 事实 | 事实 + 条件 / 位置 | 文件、路径 |
| preference | 用户 + 偏好 | 偏好 + 适用场景 | — |
| procedure | 动作 + 对象 | 步骤 + 前置条件 | 脚本、命令 |
| event | 时间 + 事件 | 发生了什么 + 结果 | 相关文件 |
| entity | 名称 + 身份 | 角色 / 职责 / 联系方式 | 链接、工单 |

星座自动建议默认开启；在新增 20 颗星或用户点「整理」时计算，不在每次打开时重算。

算法：先用文本相似度 + 共享标签 + 现有边构图，做标签传播聚类（最小 3 颗、单次最多 8 簇）；再对每簇做一次离线 LLM 命名（最多 8 条标题作为输入），失败时回退到最高频标签。命名模型跟随当前会话模型；命名结果按簇签名缓存，用户可改名 / 合并 / 解散。

### 4.2 Map

```jsonc
{
  "id": "map_...",
  "kind": "public",                  // public|project
  "name": "项目A",
  "color": "#7FD8FF",
  "description": "",
  "workspaceId": "ws_...",           // project 才有
  "createdAt": "...",
  "updatedAt": "...",
  "schemaVersion": 1
}
```

### 4.3 Edge

```jsonc
{
  "id": "ed_...",
  "from": "st_...",
  "to": "st_...",
  "relation": "related",             // related|supports|contradicts|derived|part-of|supersedes
  "createdBy": "model",              // model|user
  "createdAt": "..."
}
```

### 4.4 Constellation

```jsonc
{
  "id": "co_...",
  "mapId": "map_...",
  "name": "工具链",
  "starIds": ["st_...", "st_..."],
  "auto": true,
  "color": "#FFD479",
  "createdAt": "..."
}
```

### 4.5 Trace

```jsonc
{
  "sessionId": "s_...",
  "turn": 3,
  "step": 1,
  "kind": "brief",                   // brief|recall
  "starIds": ["st_...", "st_..."],
  "chars": 320,
  "topScore": 0.62,
  "at": "..."
}
```

每会话保留最近 200 条，供「召回 N 条」浮层读取。

### 4.6 状态机

```
pending ──点亮──▶ active ──归档──▶ archived
   │                 ▲  │              │
   └──丢弃──▶ rejected  └──恢复────────┘
```

- `rejected` 软删除，7 天后清理；
- `disputed` 是独立标记，不占状态位；
- 合并后的星保留 `mergedFrom`，状态仍为 `active`。

### 4.7 版本与迁移

- 每个星图文件带 `schemaVersion`；
- 加载时低版本自动迁移，迁移前复制 `backup-v<N>-<date>.json`；
- 导出格式带 `format` + `version`，导入时校验，不兼容则拒绝并提示；
- 旧版 `body` 迁移为 `fact`，`reason` / `condition` 留空。

## 5. 写入

### 5.1 工具

模型可见 4 个工具：

| 工具 | 用途 |
|---|---|
| `memory_search` | 按文本 / 类型 / 标签检索，默认范围 = 公共 + 当前项目图 |
| `memory_save` | 保存一条记忆 |
| `memory_link` | 建立两颗星之间的关系 |
| `memory_forget` | 归档一条错误 / 过时的记忆 |

### 5.2 memory_search

```jsonc
// 入参
{
  "query": "string",
  "types": ["decision"],
  "tags": ["工具链"],
  "limit": 8
}
// 出参
{
  "stars": [
    {
      "id": "st_...",
      "title": "...",
      "fact": "...",
      "type": "decision",
      "tags": ["..."],
      "map": "项目A",
      "weight": 0.82,
      "updatedAt": "2026-11-07"
    }
  ]
}
```

### 5.3 memory_save

```jsonc
// 入参
{
  "title": "项目使用 pnpm",
  "fact": "所有安装与脚本统一走 pnpm，禁止 npm/yarn。",
  "reason": "lockfile 一致性与 CI 缓存。",
  "condition": "仅限本仓库；临时脚本可用 npx。",
  "type": "decision",
  "tags": ["工具链"],
  "refs": ["pnpm-lock.yaml"],
  "confidence": 0.95,
  "importance": 0.7,
  "target": "auto"                   // auto=当前项目图；public=公共星云
}
// 出参
{
  "status": "saved",                 // saved|pending|merged|conflict|rejected
  "id": "st_...",
  "message": ""
}
```

`message` 用于错误 / 状态说明，避免与星的理由字段重名。

保存规则：

1. `target = public` → `pending`；
2. 项目图且 `confidence >= 0.85` → `active`；
3. 项目图且 `confidence < 0.85` → `pending`；
4. 与已有星相似度 > 0.8 → 合并；
5. 相似度 0.6~0.8 → 建 `related` 边；
6. 检测到反转语义（不要 / 改用 / 不是 / 停止 / 换成）→ 建 `contradicts` 边，旧星标 `disputed`；
7. 命中敏感或指令式内容 → `rejected`。

### 5.4 memory_link

```jsonc
{
  "from": "st_...",
  "to": "st_...",
  "relation": "supports"             // related|supports|contradicts|derived|part-of
}
```

两颗星必须在模型可见范围内；跨项目图拒绝。

### 5.5 memory_forget

```jsonc
{ "id": "st_...", "reason": "已改用 bun" }
// 出参：{ "archived": true }
```

只归档，不物理删除；硬删除只允许用户在 UI 操作。

### 5.6 去重与合并

- 相似度 = 标题（×2）+ fact（×2）+ reason + condition + 标签 + refs 的字符二元组 Dice 系数；
- 合并保留旧 id，fact 取新的（用户可改），reason / condition 去重拼接，标签并集，重要度取 max，置信度取 max，召回次数相加，来源合并，`version + 1`；
- 旧 id 记入 `mergedFrom`，边重新指向幸存者。

### 5.7 限额与幂等

- 每轮最多 3 条，每会话每小时最多 20 条；
- 同会话内相同标题 10 回合内不重复保存；
- 幂等键 = `mapId + normalized(title) + normalized(fact)`，命中直接返回已有 id；
- 超限返回可读错误，不静默丢弃。

### 5.8 模型侧记忆守则

系统提示词段落（英文完整 + 中文精简，合计约 210 token）：

```text
You have a long-term memory system called Memory Stars.

Search memories before answering when prior context may matter, and
before editing a file or running a command. Save only stable, reusable
information: explicit preferences, identity, decisions, conventions,
lessons, and important entities. Never save transient state, tool
output, code or logs, credentials, one-off instructions, or guesses.
At most 3 saves per turn; search first to avoid duplicates. When the
user says "remember this", save it with confidence 0.95. Inferred
memories go to the nebula for confirmation. Write memory content in
the user's language. If a memory conflicts with the conversation,
follow the conversation and mention the conflict.

需要背景、改文件、跑命令前，先查记忆。只存稳定可复用的信息：明确
偏好、身份、决策、约定、经验、重要实体。不存临时状态、工具输出、
代码日志、凭据、一次性指令、猜测。每轮最多 3 条，先查重。用户说
「记住」时按 0.95 存。推断的记忆进星云待确认。记忆内容用用户的
语言。记忆与当前对话冲突时，以对话为准并说明。
```

工具描述保持英文，字段语义由工具 schema 承担；系统段双语是为了让模型在中文对话里也稳定遵守。

每轮结尾自检（追加在守则后）：

```text
At the end of each turn, briefly check whether anything stable and
reusable was learned. If so, save at most 3 memories. Prefer explicit
user statements. If the user says "remember this", always save it.
每轮结束前自检：这轮有值得记的稳定信息吗？有就最多存 3 条。
```

### 5.9 敏感与指令过滤

- 凭据类：`sk-*`、`ghp_*`、`AKIA*`、`-----BEGIN * PRIVATE KEY-----`、`password[:=]`、18 位身份证、16~19 位银行卡；
- 指令类：`ignore previous`、`system:`、`you are now`、`请忽略`、`从现在开始`、工具名注入；
- 命中后拒绝入库，并提示模型转告用户；
- 过滤规则可在设置页扩展，不可关闭凭据类。

### 5.10 对话中的写入流程

1. AI 识别候选（明确“记住”、稳定偏好、决策、踩坑）；
2. `memory_search` 查重；
3. `memory_save` 提交；
4. Host 校验，补全 `source` / `anchor`；
5. 去重 / 合并 / 冲突；
6. 定状态（项目图 ≥0.85 active，否则 pending；公共图一律 pending）；
7. 内存 → 索引 → journal；
8. 返回 `{status, id, message}`；
9. 客户端刷新：内联星卡、画布新增星、星云角标、回合尾部「摘星 N · 召回 M」；
10. 下一轮可被召回。

内联星卡通过 `tool.call.toolview`（key `memory_save`）注册：已记录显示「查看 / 撤销」，待确认显示「查看 / 确认 / 撤销」。

## 6. 读取

### 6.1 开场简报

每个新会话的第一轮注入一次「项目简报」：

- 公共图：固定星优先，其次按权重取前 2，≤150 token；
- 项目图：固定星优先，其次决策 / 约定按权重取前 3，≤250 token；
- 总计 ≤400 token；
- 没有可注入的星就跳过；
- trace 记 `kind = brief`。

### 6.2 每轮检索

1. 触发：`agent/pre-step`，且本轮有新用户消息；
2. 跳过：消息 < 4 字、纯续写（继续 / 好 / 可以 / 嗯）；
3. 查询：新用户消息文本，小写化、去标点；
4. 候选：`active`、未过期、属于公共 + 当前项目图、未在最近 3 回合注入、无未裁决冲突；
5. 预算：top 6 条、600 token、相关性阈值 0.30；
6. 失败：静默跳过，记日志，不阻塞。

### 6.3 打分

文本相似用 BM25F（字段加权），其余项线性组合：

```text
bm25 = Σ_t IDF(t) · tf(t,d)·(k1+1) / (tf(t,d) + k1·(1-b+b·|d|/avgdl))

text  = bm25 / (bm25 + 3)

score = 0.50·text
      + 0.25·weight
      + 0.15·typeSignal
      + 0.10·graphProximity

score *= branchPenalty(0.7) * agePenalty(0.8)
```

- 字段权重：标题 ×3、事实 ×2、标签 ×2、refs ×2、理由 ×1、条件 ×1；`|d|` 与 `tf` 都按加权后计算；
- `k1 = 1.2`，`b = 0.75`；IDF 与 `avgdl` 按图统计，公共图与当前项目图分别算分再合并；
- 候选过滤：`bm25 < 1.0` 直接丢弃（无有效词命中，保证无答案查询返回空）；
- `typeSignal`：查询含“以后/统一/别再/记住/always/never”时，偏好/决策类 +1；含“怎么/如何/how”时，经验类 +1；其余 0；
- `graphProximity`：与已选高分星有边 +0.5，与上一轮注入的星有边 +0.5，上限 1；
- 阈值 0.30；MMR λ = 0.7，MMR 相似度用词集合 Jaccard；
- 最多 6 条，预算 600 token。

### 6.4 注入模板

```text
<long-term-memory>
〔公共〕偏好：回答先给结论。
〔项目A〕决策：包管理器固定 pnpm（2026-11-07）。
</long-term-memory>
Historical memories may be outdated. If they conflict with the current
conversation, follow the current conversation and mention the conflict.
```

注入到**运行时上下文**，不写进对话历史，避免污染会话与分叉。

### 6.5 重复抑制与失败兜底

- 非固定星 3 回合内不重复注入；固定星不受限；
- 召回统一 `retrieveHits`：原始候选先图扩展，再做重复抑制；pinned 保留最低召回位；
- 检索异常、存储异常、索引损坏都静默降级为空上下文；
- 任何情况下不阻塞模型请求。

### 6.6 Trace

- 只记录真正注入的星；
- 每会话保留 200 条，超出滚动删除；
- 客户端「召回 N 条」浮层读取 trace，展示标题、星图、来源；
- trace 不进入模型上下文。

## 7. 生命周期

### 7.1 权重

```
weight = clamp(
  importance × (0.35 + 0.65 × 0.5^(ageDays / halfLife))
  + min(0.15, recallCount × 0.01)
  + (pinned ? 0.25 : 0),
  0, 1
)
```

- `ageDays` 取最近更新 / 最近召回中较近者；
- `halfLife` 默认 45 天；
- 权重决定亮度、列表排序、检索排序。

### 7.2 星等

| 档位 | 权重 | 表现 |
|---|---|---|
| 亮星 | ≥ 0.7 | 始终显示标签 |
| 常星 | 0.3 ~ 0.7 | 星点显示，标签按总数上限显示 |
| 暗星 | < 0.3 | 默认隐藏标签，可开启“显示暗星” |

### 7.3 时效与冲突

- 决策类超过 30 天：检索分数 ×0.8；
- 未裁决冲突：旧星不自动注入；
- 新星注入时附“存在未裁决冲突”提示；
- 用户裁决三选一：以新为准 / 保留双方 / 合并；
- 日常用本地启发式检测；用户可在星详情点「复核冲突」触发一次离线 LLM 检查。

### 7.4 归档与星尘

- 归档 = 进暗星区，可恢复；
- 硬删除仅用户可操作，二次确认；
- 星尘永久保留：每次编辑 / 合并记录字段级差异，每 50 版压缩成「基线 + 增量」，历史不丢；
- 回收站永久保留，不自动清理；用户可在设置页手动清空。

### 8.3 画布交互

- 无缩放：拖拽上下左右平移；滚轮切换星图；
- 全沉浸模式不响应拖星 / 建边 / 右键菜单；
- 点击星座聚焦，其他星淡出；点击空白 / Esc 取消；
- 编辑模式下双击空白 → 快速表单：标题与事实必填，理由 / 条件 / 类型 / 标签可选；
- 全沉浸下双击空白只给提示「手动建星请切到编辑模式」，不弹表单；
- 双击星：编辑模式打开详情并聚焦标题；全沉浸模式居中显示只读预览；
- 默认力导向布局，稳定后可冻结；
- 拖星固定位置，从星拖到星建关联；
- 单击开详情，Shift 多选，右键菜单；
- 搜索定位并高亮；
- 重算布局 / 冻结布局；
- 底部状态栏：星云数、暗星数、总数、排序方式。

### 8.4 列表视图

- 卡片流：标题、类型、标签、权重、更新时间、来源；
- 排序：权重 / 时间 / 类型；
- 支持批量归档、批量打标签、批量合并。

### 8.5 星云

- 每图一个待确认区，另有跨图汇总视图，按星图分组；
- 默认逐条确认、默认不选中；只用复选框多选，表头复选框全选当前筛选结果；
- 批量操作：点亮 / 丢弃 / 打标签；超过 5 颗弹确认，列出低置信数量；
- 操作后 10 秒 toast 可整体撤销；
- 卡片动作：点亮 / 编辑后点亮 / 合并到已有 / 丢弃；
- 筛选：类型、置信度分段、时间、来源、标签、搜索；
- 侧栏角标显示全局待确认数。

### 8.6 星详情卡片

1. 头部：类型徽章 + 标题（就地编辑）+ 权重条 + 更多菜单；
2. 事实 / 理由 / 条件：三段就地编辑、标签 chips、重要度滑杆；
3. 来源：会话跳转、原文片段（前后各一句）、创建时间、创建者、置信度；
4. 统计：召回次数、上次召回、权重构成 tooltip；
5. 关系：按关系类型分组的边列表 + 添加关系；
6. 冲突条：有争议时顶部横幅 + 裁决按钮；
7. 操作：固定、归档 / 恢复、合并、移动、提升为公共星、删除；
8. 底部：id 复制、星尘历史（永久版本）。

编辑失焦自动保存，每次保存前生成一版快照，可撤销到上一版；5 秒内的连续编辑合并为一版，避免版本爆炸。

移动 / 提升只允许用户操作：移动会切到目标项目图并重设锚点，跨图边会提示数量后丢弃；提升到公共图需二次确认，确认后清除锚点并直接生效。

### 8.7 会话内元素

- `conversation.input.left`：当前绑定项目图 chip；标签为「公共 + 项目名」或「仅公共」，点击在项目图与仅公共之间循环；公共星图始终参与召回；

- `conversation.chat.turnTail`：回合末尾一行「✦ 摘星 N · 召回 M」，点击展开浮层；

## 10. 架构与性能

### 10.1 加载与索引

- 内存只保留公共图 + 当前绑定图，LRU 缓存 8 张；
- 每图一份混合倒排索引：CJK 按字二元组，拉丁按词切分；
- 索引保存 `postings`、`df`、`avgdl`、字段长度等 BM25 统计，docs 以 starId 为键；
- 写入后记录 dirty star id；下一次检索只增删这些星的 docs / postings / df，不重建全图；
- 启动时先按 2500 星分片预热索引，再开放记忆 API；`prewarmOnBoot=false` 可关闭；打开大图也会触发预热点；
- 直接命中不足时，按关系边扩展邻居，扩展分数为主命中分数的 0.42 倍；
- 检索只评分倒排候选，并用覆盖率门槛过滤长查询的部分命中；

### 10.2 持久化

- 地图全量快照 + append-only journal；
- 单星 upsert/delete、边/星座 upsert/delete、召回 stats 追加到 `*.journal.ndjson`，启动时回放；
- 设置 `journalFsync: true` 时 journal 追加后 fsync；profile 级 `plugin.lock` 阻止多进程同时写；
- 手动 `POST /stars` 与模型 `memory_save` 共用 `upsertStarToMap`，同样做相似合并、连边和 history；
- journal 超过 8MB 或插件卸载时压缩回全量快照；
- 召回统计追加 `stats` 记录，30 秒批量保存，避免每 turn 重写整图；

### 10.3 并发

- 每图一个串行写队列；
- 版本号乐观锁，冲突时返回最新版本；
- 读路径无锁；
- 多窗口通过 Host 事件同步变更。

### 10.4 指标

健康度面板（详细集）展示：

- 延迟：检索 p50 / p95 / p99；
- 召回：注入率、平均注入条数、平均 token、重复抑制命中数；
- 写入：保存数、合并数、去重率、冲突数、待确认数；
- 质量：命中率 = `memory_search` 调用返回 ≥1 条的比例，按调用命中计算，不采集用户反馈；
- 成本：每日注入 token、每日保存数、token 趋势曲线；
- 规模：星图数量、总星数、单图最大星数、磁盘占用；
- 健康建议（如「3 条冲突待裁决」「公共区 7 天未确认」）。

### 10.5 规模目标

| 指标 | 目标 |
|---|---|
| 总星数 | 10 万 |
| 单图星数 | 1 万 |
| 日会话数 | 1000+ |
| 检索 p95 | < 10ms |
| 保存 p95 | < 5ms |
| 启动加载 | < 500ms |

### 10.6 数据布局与导出

磁盘布局：

```text
<插件数据目录>/
  index.json                  # schemaVersion + 星图清单 + 统计
  maps/<mapId>.json           # 图 + 星 + 边 + 星座（当前状态）
  maps/<mapId>.journal.jsonl  # 写前日志
  maps/<mapId>.idx.json       # BM25 索引，可重建，不导出
  history/<mapId>.jsonl       # 版本差异，按图分片
  backups/auto-<date>.zip     # 迁移 / 导入前自动备份
  plugin.lock                 # profile 独占锁，退出时释放
```

默认路径：`<DSH_PROFILE_DIR>/plugin-data/rian-memory-star-path/`。

- 快照原子替换（临时文件 + rename）；
- journal 追加写、异步刷盘；每 60 秒或 100 次操作快照并截断；
- 崩溃恢复：快照 + 重放 journal，尾部损坏丢弃最后一条；
- 历史按图一个 jsonl，字段级 diff，每 50 版一条 baseline，5 秒内连续编辑合并；
- 索引可重建，不参与导出。

导出包：

```text
rian-memory-star-<date>.zip
  manifest.json
  settings.json        # 可选
  maps/<mapId>.json
  history/<mapId>.jsonl
```

- manifest 含 `format` / `version` / `schemaVersion` / `exportedAt` / 文件 sha256；
- 设置是否随包导出由开关控制，不含凭据；
- 导入逐图询问同名冲突（新建副本 / 合并 / 取消），id 全部重映射；
- 导入先解压到临时目录并校验，失败则丢弃，现有数据不动；
- 自动备份保留最近 5 份；
- 体量参考：10 万星约 35~50 MB，含历史约 75 MB，zip 压缩后约 30~50%。

## 11. DSH 集成

### 11.1 Host 侧

- 依赖服务：`tools`、`systemPrompt`、`agents`、`sessions`、`workspaceRegistry`、`llm`、`webServer`；
- `agent/created`：读 `session.header`（`cwd`、`origin`、`delegationDepth`、`agentPreset`），识别子代理；在该 `agent.ctx` 上注册 scoped `systemPrompt.context`；
- `agent/pre-step`：有新用户消息时检索，结果按 `agent.id + turn + step` 缓存；
- `systemPrompt.context`：只读缓存，不在装配阶段做检索；
- `tools.register`：4 个工具；写操作加 `tools.guard`，子代理拒绝；
- `workspaceRegistry.resolveByPath(cwd)`：把会话映射到工作区，再映射到星图；
- `webServer.register`：JSON API 路由，见 11.5；
- 数据目录：`<DSH_PROFILE_DIR>/plugin-data/rian-memory-star-path/`。

### 11.2 Client 侧

| 槽位 | 注册 | 用途 |
|---|---|---|
| `sidebar.panellist` | `id: rian-memory-star` | 入口图标 + 角标 |
| `main` | `key: rian-memory-star` | 主面板 |
| `settings.section` + `settings.section.icon` | `id: rian-memory-star` | 设置页 |
| `conversation.input.left` | `id: memory-chip` | 当前绑定图 chip |
| `conversation.chat.turnTail` | `id: memory-trace` | 「召回 N 条」浮层入口 |

- `main` 面板不绑定会话；用 `useSessions` 取当前会话，再查绑定；无会话时展示公共图；
- 主题用 `theme` 服务，文案用 `locale` 服务；
- 侧栏 `id` 与 `main` 的 `key` 必须一致，shell 负责按钮与选中态。

### 11.3 Config 与设置

- 面向开发者的兜底项放 `Config`（cordis.patch.yml）；
- 面向用户的偏好放插件自己的设置存储，由设置页写入；
- 两者不要重复。

### 11.4 禁止事项

- 不新增会话事件类型；
- 不写 `document.body`；
- 不 `require` 宿主 Client 包；
- 不在插件里替换 shell。

### 11.5 数据通道

客户端通过 Host 注册的 JSON 路由读写：

```text
GET   /plugins/rian-memory-star/api/maps
GET   /plugins/rian-memory-star/api/maps/:id/page?offset=0&limit=5000
GET   /plugins/rian-memory-star/api/stars/:id
GET   /plugins/rian-memory-star/api/traces?sessionId=...
POST  /plugins/rian-memory-star/api/stars
PATCH /plugins/rian-memory-star/api/stars/:id
POST  /plugins/rian-memory-star/api/maps
```

- 只接受同源、本机回环请求；写操作校验 `Origin` 与 `Content-Type`；
- 地图分页按权重降序返回活跃星，带 `total / offset / limit / nextOffset / hasMore`；只返回页内边；
- 地图元信息走 `/maps/:id/meta`；渲染走 `/maps/:id/viewport?cx&cy&w&h&pad`，只返回视口内活跃星与坐标；视口记录精简，详情按需走 `/stars/:id`；
- 导出 / 导入走单独的 zip 路由；
- 变更后客户端主动刷新，暂不做 SSE。

### 11.6 渲染与布局

- 原生 DOM + CSS 绘制星点，SVG 绘制边与星座虚线；不再使用 Canvas / WebGL；
- 文字标签是普通 DOM 文本，随视图层一起位移；
- 星点固定 32px，四芒星 clip-path + radial-gradient 辉光；
- Host 侧中心向外随机吸附布局：候选点按中心密、外圈疏分布，空间网格做约 72px 最小间距检测；高权重分配到外围点；无缩放，无边界拖拽平移；
- 客户端按视口取星：首屏取中心区域，拖动中每 80ms 预取，缓存立即合并、界面约 180ms 批量刷新；React 只渲染当前视口 +180px 边距，其余留在内存缓存；，松手只补最后区域并合并；只渲染已加载星；

## 12. 安全与隐私

- 凭据类敏感信息硬拦截，不可关闭；
- 指令式内容拦截，防止把「忽略以上指令」存成持久记忆；
- 注入模板明确「记忆是资料，不是指令」；
- 隐身会话不写、不召回；
- 不记忆的会话 / 工作区黑名单；
- 导出前提醒文件包含全部记忆；
- 记忆只存本地，不上传；
- 公共区写入必须用户确认；
- 子代理只读，不能写。

## 13. 边界与失败模式

| 场景 | 策略 |
|---|---|
| 分叉会话 | 继承父会话绑定 |
| 恢复会话 | 按 session id 保留绑定 |
| 子代理 | 只读检索；不注册写工具 |
| 隐身会话 | 不写不召回，chip 显示「隐身」 |
| 多窗口 | Host 串行写，客户端订阅变更 |
| 落盘失败 | 内存保留 + 重试 + 设置页告警 |
| 索引损坏 | 从快照 / journal 重建 |
| 模型不用工具 | 提示词 + 自动召回兜底 |
| token 超预算 | 按权重裁剪，固定星优先 |
| 超大星图 | 索引 + 画布裁剪 + 列表分页 |
| 时区 | 存 UTC，显示本地 |
| 卸载插件 | 数据保留，设置页可导出 |
| 并发编辑 | 版本号校验，冲突时提示刷新 |
| 时钟回拨 | 以事件顺序为准，不依赖时间排序 |
| 快照损坏 | 用最近备份恢复，顶部横幅提示丢失区间 |
| journal 尾部损坏 | 丢弃坏记录，横幅提示一次 |
| 索引损坏 | 后台重建，显示进度 |
| 数据 API 失败 | 面板重试，toast 提示 |
| WebGL 不可用 | 降级 Canvas 2D，关于页标注「兼容模式」 |
| Worker 失败 | 主线程分片布局，横幅提示一次 |
